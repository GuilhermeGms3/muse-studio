# Design System

O Design System do Muse Studio define uma interface de workspace modular para músicos. Ele não busca parecer minimalista, SaaS, dashboard ou sistema administrativo. Ele busca parecer um estúdio profissional: claro, organizado, confortável durante horas e capaz de revelar complexidade no momento correto.

## Identidade

Muse Studio é:

- Workspace modular.
- Estúdio musical pessoal.
- Ambiente de estudo, prática, repertório, revisão e composição.
- Sistema de abas, cards, painéis, inspector, dock e busca global.

Muse Studio nunca deve parecer:

- ERP.
- CRM.
- Dashboard corporativo.
- Landing page.
- Aplicação de equipe.
- Sistema de métricas gigantes.

## Princípios Visuais

- Workspace é protagonista.
- Abas são protagonistas.
- Cards são protagonistas.
- Conteúdo é protagonista.
- Menus auxiliam, não comandam a experiência.
- Ferramentas aparecem apenas no contexto certo.
- Cor comunica estado, prioridade e contexto, nunca decoração.
- O sistema deve suportar muitas funcionalidades sem parecer caótico.

## Personalidade Visual

Palavras-chave:

- Organizado.
- Preciso.
- Leve.
- Concentrado.
- Modular.
- Profissional.
- Musical.
- Explorável.

Evitar:

- Brilho excessivo.
- Gradientes decorativos.
- Sombras grandes.
- Cards gigantes sem função.
- Ícones ilustrativos demais.
- Paleta saturada.
- Visual corporativo.

## Direção De Tema

O tema primário recomendado é claro:

- Fundo geral em cinza muito suave.
- Cards e superfícies em branco.
- Divisores e bordas em cinza claro.
- Texto em cinza escuro.
- Cores contextuais discretas.
- Poucas áreas escuras, usadas apenas quando ajudam foco ou densidade.

Um tema escuro pode existir no futuro, mas deve ser derivado dos mesmos tokens e não inverter cores de forma automática.

## Hierarquia Principal

1. Title bar e status bar: orientação persistente.
2. Sidebar contextual: navegação.
3. Tab bar: superfícies abertas.
4. Workspace: trabalho principal.
5. Cards e painéis: módulos.
6. Inspector e dock: apoio contextual.
7. Command palette: salto rápido.

## Regras Absolutas

- Nenhuma funcionalidade existente deve desaparecer do sistema visual.
- Nenhum macro contexto deve expor todas as funcionalidades de uma vez.
- Toda tela deve responder uma pergunta principal.
- Toda ação principal deve ser visualmente clara.
- Toda superfície interativa deve ter hover, focus, pressed, disabled e loading quando aplicável.
- Ícones estruturais devem ser vetoriais e consistentes, nunca emoji.
- Componentes devem usar tokens sem valores arbitrários por tela.
