# Product Philosophy

Muse Studio is built on one central idea: complexity is welcome when it belongs to the craft, but complication should not come from the interface.

Music study is naturally complex. A guitarist may move between bends, intonation, repertoire, scale theory, metronome work, recordings, ear training, and composition in the same hour. Muse Studio should support that richness without forcing the user to mentally rebuild the system every time they open it.

## Core Philosophy

The product should behave like a studio desk:

- The current context is visible.
- The active work is central.
- Supporting tools are nearby.
- Deeper material is discoverable.
- Related objects can stay open.
- The user can move between study, practice, and creation without losing state.

## Reduce Cognitive Load, Not Power

The goal is not simplification by deletion. The goal is better sequencing.

Muse Studio should hide unnecessary decisions until they matter:

- The user chooses a macro context first.
- The product then shows only the relevant contextual menu.
- Selecting a concrete object or action opens a tab.
- Each tab reveals modules according to the task.
- Advanced tools live in inspectors, docks, menus, or command search.

## Workspace Over Dashboard

A dashboard summarizes. A workspace lets the user work.

Muse Studio can show summaries, but they must serve action. The home view should feel like a starting station with today's session, current song, next objective, recent projects, and quick notes. It should not become a KPI wall.

## Exploration As A Product Value

Musicians learn through association. A concept connects to an exercise, a song section, a recording, a mistake, a project idea, and a future goal.

The interface should encourage this:

- Skill nodes lead to lessons, exercises, songs, and next skills.
- Songs reveal techniques, sections, practice plans, and recordings.
- Practice sessions create diary evidence.
- Diary entries point back to skills, exercises, and repertoire.
- Projects keep creative fragments connected to musical learning.

## Muse Studio Design Tenets

- Context before feature list.
- Action before analytics.
- Cards before dense pages.
- Tabs before route-only navigation.
- Inspector before permanent clutter.
- Search before deep menu hunting.
- Musical objects before technical modules.
- Evidence-based mastery before gamification.
- Local personal ownership before cloud-first assumptions.
