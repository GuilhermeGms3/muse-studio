# Redesign Rules

These rules govern future redesign work.

## Do Not Remove Existing Functionality

All existing capabilities must be preserved:

- Home station.
- Diagnostic.
- Practice plan.
- Focus session.
- Diary.
- Library.
- Skill Tree.
- Knowledge map concept.
- Repertoire.
- Song sections.
- Song practice plan.
- Exercises.
- Exercise attempts.
- Ear training.
- Metronome.
- Projects.
- Recordings.
- Data import.
- Backup.
- Restore.
- Journal export.
- MIDI/integration area.
- Preferences.
- Future Reaper readiness.

## Do Not Turn Muse Studio Into A Dashboard

Avoid:

- Corporate KPI blocks.
- Large metric cards.
- Marketing page layout.
- SaaS language.
- Team, organization, billing, upgrade, invite, admin concepts.
- Empty hero screens.
- Generic overview pages that do not start work.

## Do Not Flatten Navigation

Do not place all features at the same hierarchy level.

Use:

- Macro context.
- Contextual menu.
- Tabs.
- Modules.

## Do Not Hide Tabs

Tabs are part of the product identity. Preserve them and make them more meaningful.

## Do Not Make Pages Dense

Tabs should be composed of cards and panels. Dense information should be progressively revealed through:

- Selection.
- Inspector.
- Expand/collapse.
- Contextual menus.
- Search.
- Docked tools.

## Do Not Group Only By Technical Category

For example, "data", "routes", "resources", or "modules" are not user mental models.

Group by musical intent:

- Practice.
- Learn.
- Library.
- Compose.
- Review.
- Tools.

## Do Not Over-Gamify

Skill states must represent mastery:

- Locked.
- Available.
- Learning.
- Practicing.
- Consistent.
- Mastered.
- Natural.
- Expert.

Avoid XP, coins, player levels, badges as primary progress, or childish game language.

## Do Not Make Integrations Dominate

YouTube suggestions, imports, MIDI, recordings, backup, and future Reaper integration are valuable but should not become the center of the product unless the user enters that context.

## Do Not Break Local-First Trust

The product should remain personal and local-first. Data tools must make storage, backup, restore, imports, and exports understandable.

## Redesign Checklist

- Does this change preserve all existing capabilities?
- Does the user first choose a context instead of a feature dump?
- Does this belong in a macro menu, tab, module, inspector, dock, or command?
- Is the view useful for musical work?
- Are advanced details revealed only when needed?
- Does the language sound like a musician's workspace?
- Would this still feel good during a two-hour practice session?
